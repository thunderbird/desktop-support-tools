Shortening your Thundermail calendar name

Your calendar is called something long with your email address in it. Here is how to change that.

Thundermail names your calendar after your account, so it arrives as something like Nemo Thundermail Calendar (nemo@thundermail.com). That is long enough to be cut off in Thunderbird's calendar list, and it puts your email address on your screen and in any screenshot you take.

First, the shortcut. If all you want is a shorter name in your own calendar list, right-click the calendar in Thunderbird, choose Properties, and type a new Name. That is the whole job: no terminal, no app password, and nothing sent anywhere. It changes only what your Thunderbird shows you — the calendar is still called the long name on the server, on your phone, and for anyone you share it with.

To change the real name, you need this script, because neither Thunderbird nor the Thundermail website can change what the server calls a calendar. The server itself is perfectly happy to, and this asks it to. You will need a terminal. Do this if you want your other devices and a fresh subscription to see the short name too, or if you want your email address out of the name for good.

1 What you need

  • An app password — not the password you type into Thunderbird. This talks to the server the old-fashioned way, which cannot use the sign-in Thunderbird normally does. Thundermail's instructions for making one: Create an App Password
    https://support.tb.pro/hc/articles/46805020320275-Create-an-App-Password
  • The address of your calendars. In Thunderbird, right-click your calendar, choose Properties, and copy Location. Then delete the last part, so it ends just after your address. An @ is written %40.
  • The tools: git clone https://github.com/thunderbird/desktop-support-tools, and uv, which runs them.

2 See what you have

export CALDAV_USER='you@thundermail.com'
CAL_HOME='https://mail.thundermail.com/dav/cal/you%40thundermail.com/'

uv run caldav_list_calendars.py "$CAL_HOME" --all

It asks for your app password, then lists your calendars and marks the default one. Copy the long name it prints — you are about to replace it, and nothing anywhere remembers it for you.

3 Try the rename without doing it

uv run caldav_rename_calendar.py "$CAL_HOME" --only default --to "Calendar"

This changes nothing. It finds the calendar, prints the name it has and the name it would have, and stops. --only takes either the name shown in Thunderbird or the last part of the address, which is why default is enough here.

4 Do it

uv run caldav_rename_calendar.py "$CAL_HOME" --only default --to "Calendar" --rename

Add --confirm if you would rather be asked first. Check the result with the listing command from step 2.

5 Putting it back

uv run caldav_rename_calendar.py "$CAL_HOME" --only default \
    --to "Nemo Thundermail Calendar (nemo@thundermail.com)" --rename

The same command with the old name — which is why step 2 asked you to copy it.

What renaming does and does not change

Your calendar has two names, and this changes only one of them:

  • The friendly name — what Thunderbird shows you in its calendar list. This is what you are shortening.
  • The address — the web address the calendar answers at, like …/dav/cal/you%40thundermail.com/default/. It was decided when the calendar was created and nothing ever changes it, renaming included.

So a calendar created as "Book club" keeps the address …/book-club/ for ever, even after you rename it to something else entirely. The address is a fossil of the original name, and that turns out to be useful: it is the one label that cannot have drifted, which is why the script accepts it too — --only default above is an address, not a name.

What to expect afterwards

  • Nothing needs re-adding. Because the address is unchanged, every device already subscribed to this calendar stays subscribed, and your events are untouched. Renaming is genuinely just a relabelling.
  • Thunderbird will keep showing the old name, and restarting it does not help. The name in its calendar list is its own copy, not the server's, and it does not go back and ask. The rename you just made is real — the listing command asks the server directly, and it is the one to trust — but you will not see it in Thunderbird until you change the name there too, which is the next item, or subscribe to the calendar afresh.
  • Thunderbird has a rename of its own, in the same Properties dialog: right-click the calendar, choose Properties, and type a new Name. That changes only what your own Thunderbird shows you. It never reaches the server, so it needs no terminal and no app password, and nobody else and no other device sees it. If a shorter name in your own calendar list is all you want, do that instead and stop here. The script is for changing what the calendar is really called: what the server says, what a new subscription picks up, and what your phone or any other calendar app shows you.

One caution. This is the only supported way to change the name right now, and it is also the reason the script asks you nothing by default: it prints what it would do and stops. Run it without --rename first, every time. A calendar you rename by mistake is put right by renaming it again — but only if you still know what it was called.

If something goes wrong

  • "The server would not accept that username and password" — almost always an account password where an app password is needed — see Create an App Password.
  • "No calendars under …" — the address is one calendar rather than all of them. Take the last part off it.
  • "This account already has a calendar called …" — two calendars with one name cannot be told apart in Thunderbird's list, so the script refuses. Pick another name.
  • "Nothing here is called …" — it lists what there is instead; copy one of those names, or use the last part of the address.
